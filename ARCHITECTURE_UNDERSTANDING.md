# Netabase Store Architecture Understanding

## Summary

The RecordStore implementation for SledStore **already exists** and works correctly. The issue is that our chat example uses a **manual trait implementation** instead of the macro system.

## Architecture Overview

### 1. Three-Layer Architecture

```
┌─────────────────────────────────────────┐
│  libp2p::kad::store::RecordStore        │ ← libp2p trait
├─────────────────────────────────────────┤
│  RecordStoreExt (netabase_store trait)  │ ← Storage backend methods
├─────────────────────────────────────────┤
│  SledStore / RedbStore / IndexedDB      │ ← Actual storage
└─────────────────────────────────────────┘
```

### 2. Components

#### A. `RecordStore` Trait (libp2p)
```rust
// From libp2p::kad::store::RecordStore
trait RecordStore {
    fn get(&self, key: &RecordKey) -> Option<Cow<'_, Record>>;
    fn put(&mut self, record: Record) -> Result<()>;
    fn remove(&mut self, key: &RecordKey);
    fn records(&self) -> RecordsIter;
    fn add_provider(&mut self, record: ProviderRecord) -> Result<()>;
    fn providers(&self, key: &RecordKey) -> Vec<ProviderRecord>;
    // ...
}
```

#### B. `RecordStoreExt` Trait (netabase_store)
```rust
// In src/traits/definition.rs:214
pub trait RecordStoreExt: NetabaseDefinitionTrait {
    fn handle_sled_put(&self, store: &SledStore<Self>) -> Result<()>;
    fn handle_sled_get(store: &SledStore<Self>, key: &RecordKey) -> Option<(Self, Record)>;
    fn handle_sled_remove(store: &SledStore<Self>, key: &RecordKey);
    fn handle_sled_records(store: &SledStore<Self>) -> RecordsIter;
    // Similar for redb, indexeddb...
}
```

**These methods are auto-generated by the `#[netabase_definition_module]` macro!**

#### C. Generic RecordStore Implementation
```rust
// In src/databases/record_store/generic_impl.rs:25
impl<D> RecordStore for SledStore<D>
where
    D: NetabaseDefinitionTrait + RecordStoreExt,  // ← Requires RecordStoreExt!
{
    fn get(&self, key: &RecordKey) -> Option<Cow<'_, Record>> {
        let (_definition, record) = D::handle_sled_get(self, key)?;  // ← Uses macro-generated method
        Some(Cow::Owned(record))
    }

    fn put(&mut self, record: Record) -> Result<()> {
        let (definition, _): (D, _) = bincode::decode_from_slice(&record.value, ...)?;
        definition.handle_sled_put(self)  // ← Uses macro-generated method
    }
    // ...
}
```

### 3. How It Works

1. **User defines models** using `#[netabase_definition_module]` macro:
   ```rust
   #[netabase_definition_module(ChatDefinition, ChatKeys)]
   mod chat {
       #[derive(NetabaseModel, ...)]
       #[netabase(ChatDefinition)]
       pub struct Message {
           #[primary_key]
           pub id: String,
           pub sender: String,
           pub content: String,
       }
   }
   ```

2. **Macro generates**:
   - `ChatDefinition` enum with all model variants
   - `RecordStoreExt` implementation for `ChatDefinition`
   - All `handle_sled_*` methods that know how to store/retrieve each model type

3. **Generic impl activates**:
   - Because `ChatDefinition: RecordStoreExt`, the generic `impl RecordStore for SledStore<ChatDefinition>` applies
   - libp2p can now use `SledStore<ChatDefinition>` as a `RecordStore`

## Current Problem

### What We Did Wrong

In `examples/simple_mdns_chat.rs` and `tests/chat_multiprocess_test.rs`:

```rust
// ❌ WRONG: Manual enum definition
enum ChatModel {
    Message { id: String, sender: String, content: String, timestamp: i64 }
}

impl NetabaseDefinitionTrait for ChatModel {
    // Manual implementation - no RecordStoreExt!
}
```

**Problem**: Manual implementation doesn't include `RecordStoreExt`, so the generic `RecordStore` impl doesn't apply!

### What We Should Do

```rust
// ✅ CORRECT: Use the macro
#[netabase_definition_module(ChatDefinition, ChatKeys)]
mod chat {
    use netabase_store::{NetabaseModel, netabase};

    #[derive(NetabaseModel, Clone, Debug, ...)]
    #[netabase(ChatDefinition)]
    pub struct Message {
        #[primary_key]
        pub id: String,
        pub sender: String,
        pub content: String,
        pub timestamp: i64,
    }
}

use chat::*;
// Now ChatDefinition implements RecordStoreExt automatically!
```

## Why Previous Attempt Failed

When I tried using the macro earlier, we got errors like:
```
error[E0277]: the trait bound `chat::Message: Value` is not satisfied
```

This was because:
1. The macro tries to generate implementations for ALL configured backends
2. `redb` feature requires types to implement `redb::Value` trait
3. We had both `sled` and `redb` features enabled via `native` feature

## Solution

### Option 1: Use Only Sled Feature (Simplest)
```toml
# In Cargo.toml for examples/tests
[dependencies]
netabase_store = { ..., features = ["libp2p", "sled"] }  # NOT "native" which includes redb
```

### Option 2: Implement redb::Value for Types
```rust
// Manually implement redb::Value if we need both backends
impl redb::Value for Message { ... }
```

### Option 3: Feature-gate the Macro
```rust
#[cfg(feature = "sled")]
#[netabase_definition_module(ChatDefinition, ChatKeys)]
mod chat { ... }
```
